# 0.0.1-beta release evidence

Resumable status updates: authenticated SSE, service-owned resume cursors, captured public job versions, printer removal events and locked printer checkpoints are now implemented. The SDK shares streams, validates sequences/ownership, refreshes snapshots after pruned history and merges job versions without submitting work. **350 .NET tests, 93 core SDK tests, eight playground tests, ten guide snippets and 22 package checks pass locally.** This includes 15 SSE/API cases and an eighth real SDK/TestServer scenario that replays across ledger reopen with zero renders/submissions/deliveries. The storage fault test was corrected to accept Windows' `UnauthorizedAccessException` for a directory occupying a file path. These changes still need a new installer candidate; live LAN/service interruption gates remain open. This supersedes the earlier SSE/SDK-pending status below.

Durable event foundation: service-side replay storage is now bounded to 2,000 events/16 MB, with stable sequence IDs and explicit cursor-gap errors. Atomic job records retain up to 256 pending version snapshots so event-storage failures do not erase status transitions or falsely reject accepted jobs. Restart, later writes and periodic maintenance retry publication. All 334 .NET tests pass, including fourteen new storage/recovery cases; API/SDK integration now runs with the durable broadcaster. Public SSE, snapshot reconciliation and SDK job/printer subscriptions remain required; this does not close the event gate. A transient renderer 503 during one full-suite run was not reproduced in the isolated rerun or subsequent full run; enhanced test-side exception capture is retained for investigation.

Nine native cases cover process exit, two-process deduplication, concurrent SDK recovery, queue independence, stale writes, capacity and corruption. A seventh real SDK/TestServer scenario uses this adapter across client/store replacement and expired service layouts with one render/delivery. All **320 .NET tests, 81 core SDK tests, nine native SQLite tests and 22 package checks** pass locally. This covers local process recovery, not machine power loss, network filesystems or cross-device ownership. Local pruning/export and live Windows/network recovery remain open.

Service-management progress: the tray now elevates a fixed action in its installed EXE, constructs commands after elevation, and uses system PowerShell without temporary script/error files. All five actions verify the exact quoted service executable before service or firewall changes; foreign, unquoted and extra-argument commands are rejected. Saved configuration and executable paths must have trusted permissions. System-only command/module lookup and a 90-second operation deadline are enforced. All **308 .NET tests** pass, including ownership rejection, lookup failure, literal Unicode paths, successful actions, missing services and timeout uncertainty. The existing prototype remains running as PID 6252; no live service or firewall was changed. Clean-host installation, UAC, runtime dependency permissions and hardware recovery pilots remain open.

Protected-settings progress: installation now initializes administrator-owned data directories; installed configuration writes use a fixed elevated tray entry point with a bounded data-only JSON request and fixed output location. Settings and Ports save asynchronously. Windows service startup rejects unsafe configuration/storage permissions and links before claiming the ledger or opening listeners, and browser/service executable checks reject user-writable paths. Existing unsafe folders are not modified or adopted. All **291 .NET tests** pass, including 13 new permission-policy, unchanged-data and isolated-save cases; existing real Chromium preparation checks pass with the installed browser's ACLs. The temporary service-management script path was replaced in the later service-management change above. No protected production directory or running service was changed during these tests.

Retention implementation: finished receipt layouts now compact after a configurable 1–365 days (default seven), while pending and delivery-uncertain receipts remain intact. Compact intent records retain exact-byte replay protection and Windows evidence across restart. Admission is bounded to 100,000 intents, 10,000 prepared receipts and a 512 MB ledger byte budget; keys are never evicted to make room. Layout expiry is exposed to POS, and capacity rejects new work without dropping accepted jobs. All **256 .NET tests pass**, including 23 new storage/endpoint/hosted-worker cases and a fourth actual SDK/service scenario covering expiry, atomic failure, corrupted records, quota recovery, restart and no duplicate delivery. Long-term export/removal, actual disk-full and process-kill-during-compaction pilots remain separate checks.

Latest API correction: all SDK connect variants now return a connected print library. Printer objects are retrieved with `await print.getPrinters()` and receipt calls use `print.target(name)`. Each returned library keeps its service binding even after another top-level connection. Server metadata is available through `print.connection`; no printer list is exposed on the library itself. All 45 SDK tests and 233 .NET tests pass, including the actual service-handler integration scenarios. No additional physical receipt was printed for this SDK change.

The operator confirmed **clear printing and successful scans of both codes**, then explicitly approved clarity. This passes the short-receipt quality baseline for this printer/driver. Long receipts, network failures and service-account deployment remain separate gates. See samples/ThermalPilot/README.md.

Network configuration correction: `localhost` is normalized to IPv4 loopback; IPv6 listener/diagnostic URLs are bracketed correctly; local diagnostics follow the configured address. Saving Basic preferences preserves an explicit bind IP unless network access is toggled. Invalid addresses/ports fail clearly before overwriting saved configuration. Regression tests cover service/tray behavior and malformed persisted addresses.

Latest scope decision: first release 0.0.1 with no backward compatibility. Use one `/api` surface and one `AccessToken`; remove prototype compatibility requirements.

Native virtual job 22 exercised the StartDoc-to-ID-save gap and was removed by AbortDoc before drawing. See samples/SpoolerIdentityAudit/README.md and PACKAGE_VERIFICATION.md for exact scope and evidence.

Runtime support gate: all projects now inherit `net10.0-windows` and runtime baseline 10.0.12, with SDK 10.0.401 pinned. All 204 .NET tests pass on the new runtime and all six sample projects build without warnings. A fresh all-transitive NuGet audit with warnings treated as errors reported no known vulnerabilities. Publication now also checks each EXE's runtime configuration for the correct framework families and patch baseline. Microsoft's September 8, 2026 support table lists .NET 10 LTS through November 14, 2028. Clean-host installation must supply x64 .NET, Desktop and ASP.NET Core 10.0.12 or a later 10.0 patch; earlier packages and historical virtual-printer/UI pilots used .NET 9 and do not prove current-runtime deployment.

SDK/service interoperability gate: three Node SDK scenarios now execute against the actual API handlers, renderer, ledger and processor using a stdio bridge to TestServer. Lost ACKs and invalid ACK digests retain the original intent; corrupted requests create no job; expired-preview replay after a store reopen returns the accepted job. One completed destination is not replayed when another waits offline across restart. Seven additional status-handler cases protect exact queue names and reject missing/duplicate names. Status uses a query parameter because encoded slashes in route segments were not preserved. No listener or installed service was launched and no Windows/physical jobs were submitted.

Service setup failure gate: the tray now checks the elevated script exit code and displays the Windows error, waits for the requested service state, and cleans up temporary scripts after failure or cancellation. Native service configuration failures and firewall failures stop setup. Executable and diagnostic paths remain literal, including Chinese text, quotes and dollar expressions. Ten new ordinary child-shell tests replace all service/firewall operations; the full .NET suite passes 191 tests. This does not verify UAC, a real install/uninstall, service-account access or fresh-logon tray behavior. The standalone install/uninstall scripts use the same failure checks.

Three real Windows Forms thread tests cover message-loop progress during blocked work, duplicate-operation rejection, later-operation acceptance, disposal with a late failure, and preservation of malformed settings.
