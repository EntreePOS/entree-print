# Entree Print documentation

Reading: an example-led documentation site for application developers, following the Entree XLSX tutorial's calm structure. This is documentation, not a marketing landing page or a replica of GitHub's UI.

- DESIGN_VARIANCE: 3. Stable reading columns and predictable section structure.
- MOTION_INTENSITY: 2. Hover, focus and copy feedback only.
- VISUAL_DENSITY: 5. Code stays readable beside short explanations.
- Native HTML/CSS/JavaScript; no framework or external assets required.
- Segoe UI/system sans for prose, Cascadia Code/system monospace for code.
- Cool neutral surfaces and one blue accent, with equivalent light/dark tokens.
- 8 px corners for controls and code panels; receipt preview preserves the saved artifact.
- Existing printer icon is reused. The preview is the saved synthetic cashier test artifact, not a simulated application screenshot. Preserve its original text and geometry, including punctuation, because it is evidence from a tested renderer.
- Copyable code, visible keyboard focus, skip link, searchable contents and responsive navigation.
- Installer availability is stated accurately. No install/download button is presented before an installer is published.

Preflight: inspect desktop/mobile and both themes; verify no horizontal page overflow, broken local links, stale snippets, unexpected network calls or hidden keyboard controls. Documentation sections intentionally share a reading layout; marketing rules about alternating feature panels do not apply to instructional content.

The playground keeps the same visual tokens, with an editor and receipt preview side by side on desktop and stacked on mobile. Browser drafts are explicitly approximate; QR/barcode placeholders are never presented as generated codes. Connecting and service rendering are explicit actions. Copyable API code follows the connected-library contract; credentials are omitted. No physical-print control is included in this preview-focused page.
